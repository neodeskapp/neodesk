This is the seventh release candidate of 3.6.0. Its headline is the receiver app: the NeoDesk app on the computers you support, installed silently with an MSI, where people get help, write to you and open tickets you answer in the console. Users get invites and password resets by email, a page of their own and bulk actions, and admins can view the console as another account. The overview is a dashboard you arrange yourself, every settings page says what a setting does and where its value comes from, and the remote viewer has one bar. Stock RustDesk clients without an API server setting now work on every install. It goes with the NeoDesk client [1.5.0-rc.9](https://github.com/neodeskapp/neodesk-client/releases/tag/desktop-v1.5.0-rc.9); the receiver app needs the client 1.5.0-rc.10 and a NeoDesk Support Agent release, see [Clients](#clients).

## Updating from 3.6.0-rc.6

Update as usual: `sudo neodesk-setup --update` on Linux, `sudo bash /opt/neodesk/docker/neodesk-docker.sh update` with Docker, `powershell -NoProfile -ExecutionPolicy Bypass -File "C:\NeoDesk\neodesk.ps1" -Update` on Windows, or **Server › Updates** in the console. Then check these points.

### Windows: run the installer's update once

The server on Windows is now a Windows service, NeoDeskServer, under its own account NT SERVICE\NeoDeskServer. Windows starts it again after a crash or a restart from the console, and `Stop-Service NeoDeskServer` stops it cleanly. An install that ran as a scheduled task under SYSTEM or as an NSSM service becomes the service at its next `-Update` or **Repair services**, with its arguments and settings kept. nssm.exe isn't needed for that.

**Server › Updates** in the console only swaps the binary, so run the installer's `-Update` once for this release. It also locks C:\NeoDesk, C:\NeoDeskConsole and C:\NeoDesk-Backups to Administrators, SYSTEM and the service account. Before, they kept the permissions of C:\, which let other users read the keys and the env file.

### Port 21114 answers other hosts with the client API only

Stock RustDesk clients with an empty **API server** send their heartbeat and system information to port 21114. Every install now answers them there, so they show their name, system and version and can sign in and use the address book.

- On Linux and Windows the whole API used to listen on 21114 for everyone. Callers from other hosts now get only the client API there, as on 21121. Scripts with API keys and Prometheus on other hosts need their addresses in the new setting `API_ALLOW_FROM` (IPs and CIDRs). An existing `METRICS_IP_ALLOWLIST` or `METRICS_PUBLIC` keeps /metrics working.
- With Docker, the update publishes 21114 and opens it in ufw or firewalld.
- Linux and Windows updates don't open 21114 in the firewall; new installs do. Open it by hand, for example with `sudo ufw allow 21114/tcp`, or with **Diagnostics** in the installer's menu.

### Linux installer backups

The backups in /opt/neodesk-backups hold the server's private key and every secret of the env file, and any local account could read them. They are now root-only, also the ones an older installer made. The installer now keeps only its newest five backups and deletes older ones when it makes a new one. To keep them all, run it as `sudo BACKUP_KEEP=0 neodesk-setup --update`. An update with nothing to install makes no backup and leaves the server running.

### Settings save with a bar

Settings pages no longer save each field on its own. You change what you want, and a bar at the bottom lists each change with its old and new value, with **Discard** and **Save** (Ctrl+S). Leaving the page with changes asks first. Risky saves, such as permissions, sign-in rules, policies and appearance, offer **Undo** in the message after saving. Only **Your account › Preferences** applies at once.

### Docker and IPv6

New Docker installs on Docker Engine 27 or newer get an IPv6 network for their containers, so the activity log and sign-in lockouts see IPv6 visitors' own addresses. Existing installs stay on IPv4. To turn it on, set `NEODESK_IPV6=true` in /opt/neodesk/docker/.env and run the update. Docker publishes IPv6 ports past ufw and firewalld, as it does for IPv4, so a port closed in ufw stays reachable over IPv6.

## What's new

### The receiver app

The receiver app is the NeoDesk app for the person at the computer: **Get help** with a code or link, **Messages** with your team and **My tickets**, in your server's branding. Installed, it runs as a Windows service, joins your server by itself and shows up under **Devices**. [The receiver app](https://docs.neode.sk/console/receiver-app/) has the details.

- **Receiver app tab.** **Devices › Add computers › Receiver app** shows the MSI properties (`SERVER`, `KEY`, `API`, `TOKEN`, `GROUP`) with copy buttons, the silent `msiexec` command for Intune, an RMM tool or group policy, and **Download installer**: a zip with `neodesk-support.msi` and an `install.cmd` that runs it with your server's values. The MSI is the NeoDesk Support Agent release imported on the **Support agents** tab. It needs **Manage joining**.
- **Rollout tokens.** **Create token** on **Device tokens** asks **For one computer** or **For many computers**. A token for many computers admits computers until it reaches **Computers allowed** (100 to start with, up to 100,000), expires or is revoked, and the list shows for example "12 joined, 88 left". Each computer gets its own device token when it joins. Revoking stops new joins and leaves the computers that joined alone. **Create rollout token** on the Receiver app tab fills it in.
- **Folder and policies on a token.** A device token can name a folder and an organization. A computer that joins with it, also with `rustdesk --deploy --token`, lands there and gets the organization's policies, in every join mode.
- **Policies the app follows.** The installed app follows **Session approval** in the organization's policies and checks them every five minutes. The new switch **People can remove the app** under **Security** hides the app from Installed apps when it is off. The Policies page says which policies the receiver app applies; the desktop app applies none yet.
- **Tickets from computers.** People open tickets in the app with a screenshot and files, read your public answers and reply. Your answers and status changes reach the app within a second and show a notification; internal notes stay in the console. **Support › Tickets** has **From computers** next to the priority, a ticket says who opened it at which computer, and the bell tells you about new tickets and replies from computers. The server adds what it knows about the computer as `computer-info.json`.
- **Offer after quick support.** At the end of a quick support session on Windows, the app asks whether to keep your company's support on the computer. **Install** joins the computer with a one-time admission that is valid for 24 hours, also on a Managed or Locked server, without a token. Turn it off under **Settings › Quick support** with **Offer to install after quick support**.

The receiver app exists for Windows only.

### Quick support

- **Feedback.** Quick support can ask the person for feedback after the session: up to 10 questions with stars, text, a choice or yes and no, set under **Settings › Quick support**. **Help requests › Feedback** lists the answers with the average stars and a filter by helper.
- **Accept by click.** The computer offers **Allow** without the one-time password only when your server confirms the caller is a signed-in helper's browser viewer, and names the helper. Any other caller needs the password. This needs the console on HTTPS.
- **Reasons.** The viewer and the quick support dialog say why a connection fails and what to do, also for a revoked or blocked computer, which they can unblock with **Unblock this computer**. Quick support never asks for a device password.
- **Opening the app.** A support link page has **Open in NeoDesk Quick Support** for a computer that has the app already.
- **The dialog** opens on **Connect** by device ID and **Make a new link**, and makes a link only when you ask for one.

### Users and sign-in

- **Invites and reset links by email.** **Add user** can send an invite, and the person chooses their own password from a link that works for 7 days. **Reset password** can send a link. **Forgot password?** on the sign-in page shows when the console can send mail and its address is set.
- **A page per user** with profile, role in plain sentences, access, sign-in, devices, tokens and activity. The users list filters and sorts from the address bar, acts on many selected accounts at once, and imports or exports accounts as CSV with a preview.
- **Sign-in security per account**: temporary passwords, a new password at the next sign-in, unlock, required two-factor sign-in, an end date that disables the account with a warning to its admins a week before, and optionally disabling accounts that don't sign in after a week's notice. The last Super admin can't be ended or deleted.
- **Sign in as** views the console as an account with fewer rights, read-only, with a bar on every page while it lasts and a notice mail you can switch off. It needs the permission **View the console as another user** and write access to Users; only super admins have it by default.
- **Your account** lists recent sign-ins and security events, takes a profile picture, which shows in the chat too, and changes your email address only once the new address confirms it. Security notices by mail can be switched off under **Settings › Sign-in**.
- **The desktop app signs in through the web console**: **Sign in with NeoDesk** opens an **Allow** page in the browser.
- **Deleting an account** shows what goes and what stays, and hands its tokens, organizations, reports and tickets to another account.

### Overview dashboards

The overview is a dashboard of widgets. **Customize** adds, moves, resizes and removes widgets: the old overview's parts, a single number, a note, links and shortcuts to other dashboards. Each account can have several dashboards as tabs. People with **Change server settings** publish shared dashboards for everyone or for chosen roles, which can open first and can be locked.

### Settings pages

Every settings page shows each setting as its name and control in one row, with the value in force and where it comes from: set here, from the server, from the environment file (locked), or the built-in default. Dependencies are named with a button to fix them, for example "Needs View devices". Roles and permissions start with a summary of what the role can do and compare roles. Policies show every control at once with **Not set** in it, so one click sets a rule. Backups run daily or weekly at a time of day and show the next run.

### Chat

- **Teams** in Team chat: standing conversations of people and user groups, set up by people with the new permission **Manage teams**. A person in a user group is in its teams while they are in the group.
- The chat has NeoDesk's own look: Support and Team as tabs, messages lined up with the header and the field, times inside the bubbles, and edge to edge on a phone. Switching between conversations shows no Loading flash.
- A computer's chat socket closes as soon as its token is revoked or replaced, or the computer is deleted or banned. While the server starts, computers are told to ask again in seconds. **Seen** on a message to a computer means the computer read it, not a colleague. A message from a computer that reopens its closed conversation shows at once on both sides.

### Mail

Every mail the server sends uses one layout, in the reader's language and time zone, with your server's name, logo and accent colour, in light and dark mode. The sender reads "NeoDesk" or "<your name> via NeoDesk", times read like "3 December 2026, 01:12 CET", and the footer says which server sent the mail and who runs it. Every mail has a plain-text part.

### Remote sessions

- **One bar**: the viewer's controls sit in one bar with labelled buttons: Displays, Keyboard, Settings, Chat, Files, More, Full screen and Disconnect. **Settings** has every option of the session, each with a line that says what it does. Settings that are on show as pressed buttons at the start.
- **Displays** is the menu for every device, and virtual displays stay in it after adding or removing one.
- The picture no longer stays smeared after skipped frames, a display in its own window follows that window's size, and the screen no longer flashes black when menus open.
- During a session the sidebar is a drawer over the screen, opened from the top bar's menu.

### Devices and fleet

- **Fleet tasks** work: resources (printers, network drives, DNS, VPN, proxy), tasks by device, folder, organization or tag, run now, once or on a schedule, compliance scans with fixes, and workflows. The computers need the client 1.5.0-rc.9.
- The device list shows the system and its main version, such as "Windows 11" or "Ubuntu 24.04", with **Full OS details** in **Columns** for the full text.
- A right-click opens the menu at the pointer on devices, folders and groups, and a click on a name ticks its box in the Columns and Tags popups.
- A double click on the edge of the menu puts it back to its default width.

### Installs and RustDesk clients

- **`rustdesk --deploy --token <device token>`** brings stock RustDesk 1.5 computers into a Managed or Locked server without **Approve** for each.
- **One host name for console and client API**: the console's port answers the client API under `/client-api`, so a reverse proxy that forwards one host name to the console carries both. Clients then get `https://<host>/client-api` as **Public API URL**.
- **Two-factor reset**: `sudo neodesk-setup --reset-password --reset-two-factor`, `neodesk-docker.sh reset-password --reset-two-factor` and `neodesk.ps1 -ResetTwoFactor` give admin a new password and turn off its two-factor sign-in, for a lone admin who lost the phone and the recovery codes.
- **Docker**: the console is published on IPv6 too, `docker stop` shuts the server down cleanly, the manager opens and closes its own firewall ports, `--import-keys <folder>` takes a RustDesk server's key pair, and `--email` for Let's Encrypt is optional. A staging certificate is replaced by a trusted one when you switch to production, and a new `--domain` takes effect.
- **Linux installer**: every question comes first and the install ends with the password and the summary, apt output is short, and `--set-config` restarts the server once. A plain HTTP address on the LAN or localhost redirects to HTTPS at the same address. An update no longer adds back keys you commented out in the env file.
- **Windows installer**: the admin's first password is in the final summary, and `-ResetPassword` resets it without the menu.
- A device that waited in Managed mode and registers after the switch to Open is approved and can start sessions. A waiting stock RustDesk client shows its name in **Join requests**.
- Client setup and invites use the first address in `RELAY_SERVERS` when **Public ID server** is empty.
- LDAP and single sign-on give the same role at every sign-in when two mapped roles tie: the group listed first wins.
- The console logs once when it sits behind a proxy that `TRUST_PROXY` doesn't trust, and the first start's log keeps to what matters.

### Several instances

The server can run as several instances on one PostgreSQL database with Valkey or Redis (`VALKEY_URL`): relay tickets and the peer directory are shared, the two legs of a relay session pair across instances, and each background job runs once. A second instance refuses to start on SQLite or without Valkey. With one server and no `VALKEY_URL` nothing changes. This isn't in the docs yet.

### Security fixes

- On Linux and Windows the whole API answered every host on 21114. See [Port 21114](#port-21114-answers-other-hosts-with-the-client-api-only).
- Windows install folders and Linux installer backups were readable by other local accounts. See [Windows](#windows-run-the-installers-update-once) and [Linux installer backups](#linux-installer-backups).
- A computer's chat socket stayed open after its token was revoked.
- A revoked or blocked computer could still start quick support or join with an invite, and showed as online.
- Fleet task results and software lists take the device from its token, not from what the computer sends.
- The Sign in as session can't be used as a normal session cookie, and the sign-in page's reset link never leads to a host the requester chose.

### Smaller changes

- The console's and the mails' accessibility follows WCAG 2.2 AA: dialogs keep screen readers inside, focus is never hidden, every page has a title, landmarks and a skip link, and text follows the browser's font size. The accessibility options are six settings saved for your account, with a pause for live updates.
- The open sessions bar shows on Remote sessions too.
- Connect in the device panel opens the session in full.

## Known issues

- A computer with a client older than 1.5.0-rc.8 has no chat outside a remote session. It shows "Not reachable now" in Support, and the server keeps your messages.
- The overview's **Client setup** widget still offers **Download RustDesk** next to **Add a computer**.
- The Docker manager's update checks the compose file and its own new copy against the release's SHA256SUMS, but doesn't check that list's signature (SHA256SUMS.sig), as neodesk.sh does.
- The receiver app's new texts are in English in the 24 languages other than English and German.
- USB and drive access can't save yet, as the banner on its page says.
- The console offers the NeoDesk agent's terminal and files only to super admins, also when another role holds those permissions.
- Revoking an API token leaves the accounts it made. Enrollment tokens of agent templates can't be revoked at all.
- `neodesk mcp` with an MCP client that can't ask you (no elicitation) still makes the agent confirm first and leaves asking you to the agent, so give an agent a token with only the permissions it needs.
- `neodesk billing clock-set` resets every setting you leave out, and `neodesk billing mail-settings-set` turns on every switch you leave out.
- On SQLite, a backup archive holds the database file twice.
- Clients that use the console's address as their API server are signed out after the session duration even while they are in use: **Extend session on activity** and **Maximum session lifetime** don't apply to them.
- Relay servers: the assignment rules are saved but not used; every device uses the default relay.
- A slow single sign-on provider ends in "OIDC authentication failed" or a bare page that says "OIDC callback proxy failed".

## Clients

Everything in this release works with the NeoDesk client [1.5.0-rc.9](https://github.com/neodeskapp/neodesk-client/releases/tag/desktop-v1.5.0-rc.9), apart from the receiver app. The receiver app, its silent MSI install and the offer after quick support need the NeoDesk client 1.5.0-rc.10 and a NeoDesk Support Agent release built from it, which come out next to this release on the [client's releases page](https://github.com/neodeskapp/neodesk-client/releases). Import the Support Agent release on **Devices › Add computers › Support agents** before you use the Receiver app tab.

Stock RustDesk clients connect as before, now also without an **API server** setting. They send no usage data and have no chat outside a session.

## Install

With Docker, the first line installs the newest release, now this one. The second also serves the console over HTTPS at your domain, which has to point at the server, with ports 80 and 443 open:

```bash
curl -fsSL https://neode.sk/install.sh | sudo bash
curl -fsSL https://neode.sk/install.sh | sudo bash -s -- --domain <domain>
```

Without Docker, on Linux:

```bash
curl -fsSL https://neode.sk/neodesk.sh | sudo bash
```

The image is `ghcr.io/neodeskapp/neodesk:3.6.0-rc.7`. The [Linux](https://docs.neode.sk/getting-started/linux/) and [Windows](https://docs.neode.sk/getting-started/windows/) pages have the details. A new install's console answers on port 3375, and on 5443 with HTTPS.
